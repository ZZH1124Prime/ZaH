# ZaH React 界面

普通界面只有应用库、管理、迁移三页。它们读取同一份应用与版本目录；任务、安装包存储、配方和内部实例属于 Go 后台，不再作为用户需要学习的页面。

- 应用库：添加名称与平台；每张卡片的加号选择安装包；版本切换、图标和运行／停止。同应用有活动版本时锁定版本选择，不同应用可以并行。
- 管理：只读检查现有依赖，默认简要反馈，展开查看结果。应用和版本弹窗均支持单选、多选及全选删除；删除前一次确认，逐项失败不移除仍存在的记录。
- 迁移：按应用选择导出，选择 ZaH 迁移包及目标目录导入；按稳定 ID 合并缺少的版本，不覆盖已有数据。恢复受依赖、绑定及后端支持范围限制；当前实测边界统一见 [就绪清单](../docs/RELEASE_READINESS.md)。

## 组件与数据流

`App.tsx` 负责三页、当前操作、确认和错误；`ApplicationLibrary.tsx` 显示应用与版本卡片；`InstallationGuide.tsx` 只为当前应用卡片补充安装包缺少的信息及 Windows 安装后入口；`HostPanel.tsx` 显示依赖检查。

`lib/operations.ts` 将用户动作转换为持久计划和任务。普通操作不暴露计划对象，进度和错误留在当前界面。提交响应不明时保留原标识；Go 也禁止同一计划因不同请求键重复执行。等待完成的安装会读取任务终态，应用启动只等待受理，以免阻塞程序运行期的停止按钮。

`useCatalogEvents.ts` 和 `lib/events.ts` 读取增量事件并更新目录。断线停止自动重试风暴，用户可重试连接。当前操作日志可展开；意外中断不自动重放，未提交操作可以核实继续或放弃。没有刷新按钮，也没有用示例记录冒充真实目录。

所有调用经过 preload、Electron allowlist 和路径选择授权，再进入 Go JSON-RPC；renderer 不拥有文件系统、shell 或任意网络权限。图标使用经过验证的本地数据，不依赖 CDN。

## 安装与生命周期

Linux 安装包有可靠版本和入口、且本地基础镜像就绪时自动继续安装；缺少版本或入口时补一次必要信息。Windows 需要区分安装器与便携程序，多个 EXE 时选择实际入口。安装器原生窗口由用户操作；结束后停止环境，保存最终 EXE，不能以安装器退出推断安装完成。

外部应用关闭窗口后，环境可能仍运行，卡片继续显示停止。ZaH 自身关闭由 Electron main 确认、停止全部受管环境并核实结果后退出；失败留窗。最小化不触发停止。不会全局停止 Docker 或 Wine。

## 检查

`npm run test:frontend` 验证三页操作、选择取消、安装、状态锁定、删除失败保留、幂等重试和增量事件。`npm run test:electron` 在独立 HOME/XDG、无头 Electron 和受限模拟 Docker 中验证真实 React/preload/Go/SQLite 链路，不是第三方应用安装验收。生产测试边界见 `docs/DEVELOPMENT_VALIDATION.md` 与 `docs/RELEASE_READINESS.md`。
