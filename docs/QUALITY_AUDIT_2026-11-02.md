本轮以 Z1 当前源码为准，检查三页普通用户流程、固定 Ubuntu 20.04 开发入口、任务状态和迁移边界。没有把昨天的构建结果当作当前源码已经通过，也没有执行用户真实安装包或永久删除。仓库与父目录没有适用的 AGENTS.md / .agents 技能。原有未提交改动保留，无 Git 写操作。

## 已做的精简与仅建议的优化

- 删除三页界面无人消费的 recipe 查询：每批目录事件不再额外读取全部配方。没有删后端配方功能或安全校验。
- stop-all 的全局禁用状态复用 `stopTaskState.batchPending`，不重复扫描任务和计划。
- 将进度/原计划恢复/取消展示从 App 的巨大 JSX 行拆出；统一使用同一个 OperationRunner 的状态对账。不是增加另一套任务框架。
- Bottle 文件和目录枚举共用原有排除规则，避免两份过滤规则漂移。
- **仅建议**：继续把 App 的删除和导入/导出编排拆成少量按用户动作划分的函数，保留现有接口；不值得为当前规模引入通用工作流引擎。把维护脚本中重复的无头测试准备步骤统一为一个测试入口，避免本轮首次隔离桌面测试遗漏源码引用的夹具问题。
- **仅建议/未实现**：目录快照、历史任务和计划仍整批读取，RPC 帧上限为 1 MiB。大量历史记录可能达到上限；需要有界当前视图与分页历史读取，不能靠无限增大帧或删除审计解决。此项是静态设计容量风险，本轮未宣称已做大规模容量压测。
