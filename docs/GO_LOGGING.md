# Worker 日志预算与安全保留

`internal/jobs/logs.go` 管理每个任务独立的 `worker-<job-id>.log`。日志位于 `$XDG_STATE_HOME/zah/logs`，目录和文件分别要求本用户拥有、0700/0600 私有权限。默认预算是每文件 64 KiB、总预留容量 16 MiB、最多 256 个文件。

## 写入与 manager 生命周期

worker 自己打开文件并持有 `worker-log-<id>.lock`；manager 不再把原始 stdout/stderr 直接重定向到无限增长的文件。这个文件和锁属于 worker，即使 manager 崩溃也不依赖原 manager 的管道。

`WorkerLog.Write` 受互斥保护且永不超过单文件预算，超出部分丢弃并尽可能写入限额标记。worker 只写固定状态摘要，不写原始错误、应用输出、命令参数、路径或凭据；详细计划、任务结果和执行证据仍在 SQLite。可恢复的 Go panic 写入固定提示，任务保持需要恢复检查的状态，不假装成功。不能捕获的进程崩溃由持久 worker 身份和任务恢复逻辑识别。

每个已存在的日志至少预留完整的 64 KiB，而不是仅计算其当前长度。因此多个空日志后续同时写满，也不会绕过总量预算。准入和保留操作共用短期 `logs.lock`；单任务文件的生命周期锁贯穿整个 worker。

## 只有证明不再写入才清理

保留程序仅识别严格命名的 worker 日志。它逐项核对：

1. 文件是本用户拥有的私有普通文件，只有一个硬链接；不跟随符号链接。
2. 对应持久任务存在且处于 succeeded、failed、cancelled、interrupted 或 waiting_user；queued、running 和 cancel_requested 不处理。
3. 日志生命周期锁和任务锁均可非阻塞取得。
4. 已记录的 PID 与启动身份已明确消失或不同；当前身份仍匹配、身份读取有不明确错误时保留。未记录身份时，仅接受明确 cancelled 且未登记 worker 的任务。
5. 打开后重新核对同一 inode、大小、所有权与链接数，删除前再次比较当前目录项。

已确认 inactive 的超大日志保留带标记的末尾；其余按旧到新删除，直到满足预算并为下一条 worker 日志预留一个槽位。每个任务独立文件就是轮转单位，不重命名或截断正在运行的任务日志。管理器启动、启动新 worker 前以及已等待 worker 退出后触发保留。

未知任务、来源不明文件、活动日志、异常权限、软链接和硬链接保持原样。旧版本遗留或不安全文件可能使已有目录暂时超预算；此时不通过删除不明内容来强行达标，新日志准入会失败，尚未执行的任务进入 interrupted 供检查。应用用例不会为了释放日志空间而删除用户数据。

## 持久证据不随日志删除

日志回收不修改 SQLite 中的 Plan、Job、Step、引用或事件。事件接口继续按游标分页、限制单次请求数量，但目前不裁剪历史；日志预算不导致重连事件缺口。独立的数据库容量/备份管理不应混同于可丢弃诊断日志。

## 自动化验证

新增测试全部在临时目录和隔离 SQLite 执行，未读取或清理用户实际日志：

- 多次超量写入、重新打开和单文件上限；
- 空活动日志的未来容量预留、总量准入失败；
- 按时间保留最新已完成日志，并保留数据库证据；
- 只截尾已证明 inactive 的日志，保留存活 PID、running、未知身份和无记录文件；
- 软链接、硬链接和外部目标不变；
- worker 日志锁和任务锁阻止清理；
- 取消的保留请求不修改文件。

`go test -race ./internal/jobs ./internal/bootstrap` 已通过。真实 manager/worker 生命周期测试另以隔离 XDG 目录验证断开、崩溃后继续运行和恢复，不能据此宣称应用后端已经实测。
